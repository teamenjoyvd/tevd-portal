# GOTCHAS — tevd-portal

Read in full during SHAPE and GATHER. Add new entries here immediately when a sharp edge is discovered — never inline in code comments alone.

| Topic | Rule |
|---|---|
| `middleware.ts` | NEVER. Use `proxy.ts`. |
| Pattern A helpers | NEVER `auth.jwt() ->> 'sub'` in RLS or the helper functions — it resolves to a Supabase Auth UUID; Clerk users have no Supabase Auth row, so `'sub'` never matches. This exact mistake has been reintroduced at least 3× (ADR-011). Before "fixing" a helper, verify against `supabase/migrations/20260315000000_baseline.sql`, not an assumption. Clerk ID lives in `request.jwt.claims ->> 'user_id'`. |
| Clerk auth | `await auth()` → `{ userId }`. No sync auth. No JWT template. |
| Clerk shadow DOM | CSS vars unavailable in Clerk components. Use hardcoded hex (`#bc4749`). |
| Role promotion | Every `profiles.role` update MUST also call `clerk.users.updateUserMetadata`. Routes: `/api/admin/verify`, `/api/admin/members/[id]` PATCH, `/api/admin/members/verify/[id]`. |
| `payments` FK | **Three** FKs to `profiles`: `profile_id` (whose ledger the row sits on), `logged_by_admin`, and `paid_by_profile_id` (who actually paid — added by 2607-DEV-676). PostgREST MUST hint every embed, e.g. `profiles!profile_id(...)` or `payer:profiles!paid_by_profile_id(...)` — without it, 500. Same trap, same class, one table over: `payment_guests` (2607-DEV-677) has **two** FKs to `profiles` — `owner_profile_id` and `linked_profile_id` — so every embed of it needs `profiles!owner_profile_id(...)` / `profiles!linked_profile_id(...)` too. The `payments` -> `payment_guests` embed is the exception that needs no hint: there is only one FK between them. |
| Guest payments and personal totals | A row with `payments.beneficiary_guest_id` set covers an ad-hoc guest who has **no ledger**, so it sits on the PAYER's `profile_id` (enforced by `payments_guest_ledger_check`). Any query or reducer computing one person's OWN total must therefore exclude it — use `personalApprovedTotal` from `lib/payments/totals.ts` rather than summing `amount` over a profile's rows. Getting this wrong tells a payer who covered themselves 100 € and a friend 100 € that they have paid 200 € of their own 100 € fee. Listing queries are unaffected and must NOT filter these out: the payer really did pay that money. |
| `types/supabase.ts` | Regenerate via `supabase gen types typescript --project-id iymwxdewcpvpjgzewtzk > types/supabase.ts` (CLI installed since #563; the Supabase MCP is turned off). Regeneration is mandatory after any migration that touches an enum; `lib/roles.ts` derives `MemberRole` and `ALL_ROLES` from this file and will emit a compile error on missing/extra keys. |
| Supabase DDL | Migration files in `supabase/migrations/`, applied to DEV via `supabase db push` (CLI is the single `schema_migrations` ledger writer). MCP `apply_migration` is allowed against DEV only, and any MCP-applied migration must be reconciled into the CLI ledger (`supabase migration repair --status applied`) before the next `db push`. Never raw `execute_sql` for DDL. Migration filename: `YYYYMMDD00NN00_description.sql` — a 14-digit version whose last six digits are a zero-padded counter (`000000`, `000100`, `000200`, …). Before writing a filename, list `supabase/migrations/` and find today's highest counter — increment by 100, reset to `000000` on a new day. Never wall-clock `HHMMSS` (session collisions) and never the old `YYYYMMDD_NNN` form — the CLI takes the digits before the first underscore as the ledger version, so `_NNN` truncates to the bare date and collides across same-day files (cause of the 2026-07-14 DEV ledger repair). |
| Migration CI | Prod DDL runs exclusively through the gated `migrate-prod.yml` workflow (`production` environment, manual approval) — never from a dev machine, never via MCP (#570). PR-time validation: `migrations-check.yml` replays all migrations on a disposable local Supabase. The old "never restore these workflows" ban (PR #309) is obsolete: the ledger-drift it guarded against is repairable via `supabase migration repair` (DEV repaired 2026-07-14); prod's ledger must be audited/repaired per `docs/runbooks/PROD_MIGRATION_LEDGER_REPAIR.md` before the first gated run. |
| Expand/contract migrations | Hard constraint: a migration merged alongside code must be backward-compatible with the currently deployed code (additive: new tables, nullable columns, new indexes). Destructive changes (drop/rename column or table, type narrowing) split across two releases — expand + backfill first, ship code that stops using the old shape, contract in a later PR. Vercel deploys on merge while the migration waits for approval, so both orders of (code, schema) must be safe. |
| Large GitHub files | `create_or_update_file` times out above ~10KB. Use `push_files`. |
| Mapbox | CDN only — never npm. Dupe guard on load. |
| Mapbox theme swap | `map.setStyle()` + `styledata` event. MutationObserver on `data-theme`. |
| shadcn install | NEVER `npx shadcn@latest init` — corrupts globals.css. Use `npx shadcn@latest add <component>`. After each add, revert any injected `@layer base` blocks. |
| shadcn CSS vars | Edit vended source in `components/ui/` to use project tokens (`--bg-card`, `--text-primary`) not shadcn defaults. |
| shadcn Tabs | NEVER `defaultValue`. Always `value={tab}` + `onValueChange` → `router.replace(?tab=..., { scroll: false })`. Wrap in `<Suspense>`. |
| `--bg-global-rgb` dark | MUST be `26, 31, 24`. Wrong value = white navbar in dark mode. |
| Admin forms | NEVER define a form component inside a parent page component — React remounts on every render. Hoist to module scope. |
| Admin Drawer | Use `components/ui/Drawer.tsx` for all admin create/edit. Exceptions: Announcements + Quick Links create = inline cards. All deletes use `AlertDialog`. |
| Route handler `params` | `params` is a `Promise` in Next.js 16. Type as `{ params: Promise<{ id: string }> }` and `await params`. |
| `useParams()` | Takes NO type argument in Next.js 16. `const params = useParams(); const id = params.id as string`. |
| `sendEmail` | Removed. Use `sendNotificationEmail` (fire-and-forget, respects config gates) or `sendTransactionalEmail` (bypasses gates, returns typed result). **Dynamic imports evade static rename tools and grep** — after any email-related rename, manually read every route using `import('@/lib/email/send')`. Known callers in `sendNotificationEmail` JSDoc. |
| `pg_net` cron | `net.http_post(...)`. NEVER `extensions.http_post(...)` — silently does nothing. |
| `TranslationKey` | Strict union. Add to `translations.ts` before using `t()` or build breaks. |
| `BottomNav.tsx` | Dead stub. Do not import. |
| Profile prerender | Guard ALL `validProfile!` accesses with `if (isLoading \|\| !validProfile) return <ProfileSkeleton />`. |
| `TeamAttendee` type | Exported from `app/(dashboard)/trips/[id]/page.tsx`. Do not redeclare. |
| Trusted RPC + service role | Any RPC that performs cross-user writes MUST be `SECURITY DEFINER SET search_path = public`. Because SECURITY DEFINER bypasses RLS, the function body MUST include an internal authorization check: `IF auth.role() <> 'service_role' AND NOT is_admin() THEN RAISE EXCEPTION 'Unauthorized'; END IF;`. Pattern A helpers return false/null under service-role with no JWT. `SECURITY INVOKER` is only safe for read-only helpers or trigger functions. |
| `supabase db push`/`reset --linked` on a fresh Cloud project | CLI does `SET SESSION ROLE postgres` then `RESET ALL` before applying migrations. `SET SESSION ROLE` does NOT pick up that role's `ALTER ROLE postgres SET search_path=...` — role-level GUCs only apply at actual authentication time, not mid-session role switches. Result: `RESET ALL` falls back to the Postgres cluster default (`"$user", public` — no `extensions`), so any migration calling `uuid_generate_v4()` unqualified (Supabase Cloud installs `uuid-ossp`/`pgcrypto` into `extensions`, not `public`) fails with `function uuid_generate_v4() does not exist`, even though the DB/role config looks correct on inspection. Fix once per project: `ALTER DATABASE postgres SET search_path TO "$user", public, extensions;` (database-level default applies regardless of connecting role) — then retry `db push`/`reset`. Discovered 2026-07-13 doing #563: `db reset --linked` on `iymwxdewcpvpjgzewtzk` wiped the whole `public` schema then failed on `20260315000000_baseline.sql`, leaving the project schema-less until this fix + a full `db push` replay recovered it. |
